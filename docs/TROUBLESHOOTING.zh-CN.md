# WePulse 故障排查（Windows）

本页按用户看到的现象给出处理顺序。不要在 Issue、聊天、截图或日志中公开 `.env`、`ADMIN_TOKEN`、`WEREAD_COOKIE`、邮件密码、Webhook 地址或数据库。

## 先做四项快速检查

1. 确认正在使用的项目目录，例如 `F:\WePulse`，不要同时启动旧版本目录。
2. 在浏览器打开 `http://127.0.0.1:8765/health`。能看到 `status: ok` 表示服务正在运行。
3. 打开管理中心 `http://127.0.0.1:8765/admin`，重新粘贴本次启动复制的管理令牌。
4. 查看 `data/service.err.log`。分享日志前必须删除凭据、个人路径和文章标识。

## 症状速查

| 现象 | 常见原因 | 优先处理 |
|---|---|---|
| PowerShell 大量中文乱码、字符串缺少终止符 | 启动脚本编码损坏 | 重新下载发布包，不要继续修改损坏脚本 |
| 无法创建或复制 `.env`，访问被拒绝 | 项目目录不可写 | 给当前账户“修改”权限，或移动到自己的 D/F 盘目录 |
| 管理中心提示无效管理令牌 / 401 | 浏览器保存了旧令牌，或旧目录服务仍在运行 | 停止旧服务，从当前目录重新启动并重新粘贴令牌 |
| 微信读书 `/api/mp/cover` 返回 400 | Cookie 不完整、登录过期、来源请求选错或上游变化 | 从主域名请求重新复制 Cookie，再执行真实检查 |
| 只能看到 `oss.weread.qq.com/river/batch` | 选中了资源子域名请求 | 刷新并操作微信读书页面，选择主机名恰为 `weread.qq.com` 的请求 |
| 点击“刷新页面”没有新文章 | 刷新只重载页面 | 点击“立即采集全部” |
| 点击“测试每日推送”没有外部消息 | 尚未配置通知渠道或渠道配置失败 | 配置邮件/企业微信/Webhook，重启后再测试 |
| 双击 restart 后只打开网页 | 正常行为 | 网页打开表示服务已重新启动；查看状态即可 |
| 关闭启动窗口后担心服务停止 | 服务使用隐藏后台进程 | 启动成功后窗口可关；用 stop 脚本正式停止 |
| 06:00 没有收到摘要 | 当时电脑关机、服务未运行、断网或渠道失败 | 恢复后手动测试推送；需要补发时配置外部重试任务 |

## 1. PowerShell 中文乱码和解析错误

典型表现包括中文变成 `棣栨...`，随后出现“意外的标记”“字符串缺少终止符”或“缺少右花括号”。乱码会改变引号等字符，因此后面的语法错误通常只是连锁反应。

处理方法：

1. 停止使用当前损坏的压缩包或脚本。
2. 重新下载项目的正式 Release，并完整解压，不要只覆盖一个 `.ps1` 文件。
3. 不要用旧版文本编辑器、网页复制粘贴或聊天软件转存 `.ps1` 文件。
4. 如果必须编辑，保存为“UTF-8 with BOM（带签名）”。
5. 重新双击 `start-wepulse.cmd`。

维护者发布前应使用系统自带的 `powershell.exe` 实际解析和运行一次所有入口脚本，而不只在 PowerShell 7 中测试。

## 2. `.env` 访问被拒绝

WePulse 首次启动需要在项目目录创建 `.env`、`.venv`、`.python`、`.uv-cache` 和 `data`。只有读取权限无法运行。

推荐图形界面处理：

1. 右键项目文件夹 → **属性 → 安全 → 编辑**。
2. 选择当前 Windows 账户。
3. 勾选“修改”，并让权限应用到子文件夹和文件。
4. 关闭属性窗口后重新启动。

如果项目来自受保护目录、其他账户或只读介质，更简单的做法是完整解压到 `D:\WePulse` 或 `F:\WePulse`。不要放在 `Program Files`，也不要长期以管理员身份运行。

PowerShell 中账户名与权限参数直接拼接容易被错误解析。确实需要命令行授权时，可在**确认路径完全正确**后使用：

```powershell
$account = "$env:USERDOMAIN\$env:USERNAME"
icacls "F:\WePulse" /grant "${account}:(OI)(CI)M" /T /C
```

## 3. 管理令牌无效（401）

管理令牌只负责保护本机管理操作，与微信读书 Cookie 不是同一个东西。浏览器把令牌保存在本机 `localStorage`，项目把实际令牌保存在 `.env`。

按顺序处理：

1. 从可能存在的旧项目目录运行 `stop-wepulse.cmd`。
2. 在当前目录运行 `stop-wepulse.cmd`，再运行 `start-wepulse.cmd`。
3. 启动脚本会把当前令牌复制到剪贴板。
4. 回到管理中心，在登录框按 `Ctrl+A`、`Ctrl+V`，点击“保存并刷新”。
5. 如果仍是 401，确认 `8765` 端口没有被另一份 WePulse 占用。

修改 `.env` 中的 `ADMIN_TOKEN` 后必须重启服务；仅刷新网页不会让后台重新读取配置。不要把令牌粘贴到聊天或 Issue。

## 4. 怎样选择正确的 Cookie 请求

1. 浏览器登录 `https://weread.qq.com/`。
2. 按 `F12` → **Network / 网络**，勾选保留日志并刷新页面。
3. 点击一个请求，在 **Headers / 标头 → General / 常规** 查看 Request URL。
4. 只选择主机名恰好为 `weread.qq.com` 的请求。
5. 在 **Request Headers / 请求标头** 中复制 `Cookie:` 冒号后的完整值。

以下请求不适合作为 Cookie 来源：

```text
https://oss.weread.qq.com/river/batch
```

如果列表里暂时只有 `oss.weread.qq.com`，在微信读书页面打开书架、搜索一本书或切换页面，让浏览器产生主域名请求。无需在微信读书里搜索公众号。

管理中心保存 Cookie 时会检查关键字段 `wr_vid` 和 `wr_skey`。Cookie 是登录凭据，不能发给项目维护者；排错时只描述“字段是否存在”，不要贴出字段值。

## 5. Cookie 检查或采集返回 400

HTTP 400 表示上游接口拒绝了当前请求，不等同于 WePulse 页面坏了。常见原因：

- 复制了响应头中的 `Set-Cookie`，而不是请求头中的完整 `Cookie`；
- 选择了 `oss.weread.qq.com` 请求；
- Cookie 已过期或账号登录状态发生变化；
- 某个公众号的旧 `bookId/source_id` 已不可用；
- 微信读书网页接口发生变化或临时限制。

处理顺序：重新登录微信读书 → 从主域名请求复制 Cookie → 在管理中心安全保存 → 点击“检查 Cookie” → 点击“立即采集全部”。如果所有订阅同时报错，优先判断 Cookie 或上游变化；如果只有一个公众号报错，用该公众号最新公开文章重新添加验证。

## 6. 启动、停止、重启和网页窗口

- `start-wepulse.cmd`：准备环境、启动隐藏后台服务、复制管理令牌、打开管理网页。
- `stop-wepulse.cmd`：停止当前目录启动的后台服务。
- `restart-wepulse.cmd`：先停止再启动，因此会再次打开网页。
- 浏览器页面：只是管理界面，关闭不会停止后台服务。
- 启动命令窗口：看到“已在后台运行”后可以关闭。

移动项目目录前应先停止服务。移动后从新目录重新安装开机自启动；否则任务计划程序仍会指向旧路径。

## 7. “刷新页面”和“测试每日推送”没有反应

“刷新页面”不会采集，它只读取数据库中的最新状态。要检查文章，请点击“立即采集全部”。

“测试每日推送”只向已经配置的渠道发送：

- 企业微信：需要 `WECOM_WEBHOOK_URL`；
- 邮件：需要 SMTP 主机、收件人、账号和应用专用密码；
- 通用 Webhook：需要 `DIGEST_WEBHOOK_URL`。

修改这些 `.env` 配置后运行 `restart-wepulse.cmd`。测试结果会记录在 `data/last_notification.json`，但公开求助前仍应检查其中没有敏感地址。

## 8. 每天 06:00 没有网络或电脑未开机

内置每日任务要求服务在设定时间运行且能联网。普通采集恢复后会按间隔继续，但错过的每日推送不会无限自动补发。

可选方案：

1. 运行 `scripts\windows\install-autostart.cmd`，并确保电脑已经登录 Windows。
2. 网络恢复后在管理中心点击“立即采集全部”和“测试每日推送”。
3. 使用 Codex、Windows 任务计划程序或其他外部调度器每 30 分钟检查一次，只在全部订阅成功后标记当日完成。

外部重试任务必须保存“当日报告是否已成功”的状态，避免同一天重复发送；Cookie、令牌只应在本机读取和使用。

## 9. Docker、WSL 与本地版

Windows 本地一键启动不需要 Docker，也不需要 WSL。只有选择 Docker 部署方式时才需要安装并启动 Docker Desktop/Engine。不要同时运行 Docker 版和本地版，否则二者可能争用 `8765` 端口。

## 10. 求助时可以提供什么

可以提供：WePulse 版本、Windows 版本、启动方式、错误发生的按钮、HTTP 状态码、经过脱敏的错误文字，以及问题是否影响全部订阅。

禁止提供：`.env`、完整 Cookie、管理令牌、邮件密码、Webhook 地址、数据库、含个人目录的完整日志。安全问题请按 [SECURITY.md](../SECURITY.md) 私下报告。
